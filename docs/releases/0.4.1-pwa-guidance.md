# 0.4.1：アプリ内ブラウザでの案内修正

2026-10-28（日本時間）。ユーザーはChatGPT・LINE等のアプリ内からリンクを開いた際に、HTTPS確認の案内を受けたと報告。

従来の実装はService Worker非対応と安全な接続でない状態を区別せず、HTTPS確認だけを案内していた。今回、安全な接続・機能の非対応・ブラウザのSecurityErrorを区別した。アプリ内ブラウザが直接の原因かどうかを端末上で断定する判定は行わない。

- HTTPSでも非対応ならSafariを直接開く手順を表示。
- URLコピー（クリップボード拒否時は手動コピー案内）、オンライン時の通常再読み込みを追加。
- 通常再読み込みでメモが残ることをテスト。
- サイトデータ削除やService Workerの強制解除は行わない。
- ブラウザ変更で保存先が別になること、JSONを保持することを案内。
- DBスキーマ・バックアップ形式・ユーザーデータは変更しない。

## 検証

- 本番ビルド成功。
- 単体65件成功。
- 関連操作テスト8件成功（モバイル4・PC4）。
- 本番PWA6件成功。通常の更新／オフライン保存に加え、非対応ブラウザ・SecurityError・コピー拒否・通常再読み込み後のメモ保持を確認。
- 実機Safariは未検証。ブラウザ自体の制限をアプリ側で解除する変更ではない。

## 公開

元のURL https://gentle-souffle-0c93dc.netlify.app/ を維持する。GitHubの公開ブランチrelease/my-memoへ統合する。ユーザーから公開許可・JSON保存済みの確認を受領済み。

Netlify管理画面の連携と認証情報はこの環境にない。公開URL・デプロイAPIへの接続は環境の403制限があるため、GitHub pushの成功とNetlifyの公開成功は分けて確認する。元のサイトの初回公開方法（Git連携／手動アップロード）を確認中。

## 元のサイトを継続して使うための設定

Netlifyの既存プロジェクトgentle-souffle-0c93dcで、Repository設定（通常はProject configuration → Build & deploy → Continuous deployment）を開く。Git未連携ならLink repository等の項目からGitHubのkjn52p4sc8-beep/mを接続する。画面上の項目名はNetlifyの表示版によって異なる。

- 公開ブランチ：release/my-memo
- ベースディレクトリ：空欄
- ビルド：npm run build
- 公開ディレクトリ：dist
- Node.js：netlify.tomlで24を指定済み

既存のサイトを更新し、新しいサイトは作らない。Deploysに最新の公開ブランチのコミットとPublishedが表示されれば配信側の更新完了。

利用者はURLをコピーしてSafariを直接起動し、アドレス欄に貼り付ける。公開後、設定の0.4.1を確認する。オフライン対応環境なら設定の更新確認を利用し、非対応なら通常の再読み込みで新しい公開ページを取得する。アプリのURLを渡しても、個人のメモが他人へ共有されるわけではない。
