# My Memo 0.10.2 — 最終品質改善・PWA点検

2026-11-05（日本時間）。既存アプリを拡張し、保存方式・画面の配置・機能を維持しました。追加ライブラリ、DB移行、ユーザーデータの初期化はありません。

## 修正・改善

- ToDoの送信・削除とメモのスワイプ削除・ピン留めに即時ロックを追加。状態の再描画を待たず二重実行を防ぎます。
- 新規ToDoの保存中に次の入力をした場合、完了時にその入力を消さず、フォーカスも維持します。送信済みToDoは保存し、次回送信には新しいIDを使います。編集・削除中のフォームは操作を一時停止します。
- ToDo保存中に別画面へ移動しても、完了時にToDo画面へ強制的に戻さないようにしました。
- 通知許可の返事が遅れて届いた時、既に変更した設定や次の空フォームへ古い結果を表示しないようにします。
- メモのスワイプ中に別の指が触れた場合、途中の移動表示を解除します。既存の縦スクロール・左右スワイプ・長押し判定を維持しています。
- 通常の文字数表示では必要なカウントだけを計算し、詳細は開いた時だけ計算。カーソル移動だけで全文を再計算しません。文字分割器を再利用し、分割結果を大きな配列に保持する処理をなくしました。日本語・絵文字・CRLF・結合文字の基準は維持しています。

## ToDoボタンと「Powered by Netlify」

アプリのソース、HTML、公開用静的ファイルに、このバッジの表示・読み込みコードは見つかりませんでした。ローカルでは320 / 375 / 390 / 430px、ライト・ダーク、下部34px等のセーフエリアを模擬して、ToDoが44px以上の領域で表示され、中心点をタップできることを確認しました。既存の配置を変えたり、第三者要素を隠すCSSを追加したりしていません。

**公開サイトでバッジがToDoを覆う問題の出所は未確認・未解決です。** この環境から公開URLへの接続はCONNECTプロキシの403、Netlify公式ドキュメントへの接続も403でした。Netlify管理画面にも接続されていないため、自動挿入・プレビュー枠・契約に伴う表示のどれかは断定できません。

確認手順（管理画面の表記は変更される場合があります）：

1. Safariのアドレス欄へ `https://gentle-souffle-0c93dc.netlify.app/` を直接入力。Netlify管理画面内のプレビューやアプリ内ブラウザの枠を介さない状態でも表示されるか確認します。
2. Netlifyの対象プロジェクトで、Project configuration（旧Site configuration）内のBuild & deploy → Post processing → Snippet injectionに該当スニペットがあるか確認します。項目が移動している場合は設定検索で「Snippet injection」を探します。自分で登録したバッジ用コードがある場合だけ、その内容を控えて無効化・削除し、再デプロイします。
3. 設定検索で「Toolbar」「Badge」「Branding」も確認します。該当する表示設定が存在する場合は本番での表示をオフにします。これらの名称のスイッチが必ず存在するという意味ではありません。契約上必須の表示の場合は、画面に示される条件・費用を確認してください。こちらで契約や有料プランを変更していません。
4. 該当設定がない場合は、表示中の画面とバッジのリンク先を確認し、Netlify側へ挿入元を問い合わせます。確認のためにサイトデータを削除する必要はありません。

## PWA

- Manifestは既存の `name/short_name: My Memo`、`display: standalone`、`start_url/scope: /` を維持。
- 深緑のシンプルなメモ帳アイコン（180 / 192 / 512px）を確認し再利用。apple-mobile-web-app-titleと標準のmobile-web-app-capableをHTMLに追加しました。
- ページへ戻った時・通信復帰時に、前回から5分以上ならService Workerの更新を確認。並行実行・短時間の繰り返しを抑え、画面表示中だけ実行します。ポーリングや自動の更新適用・再読み込みは行いません。
- 設定を開くと待機中の更新を表示するため、既にダウンロード済みの更新を見るための確認タップを省けます。
- 更新適用の二重実行を防ぎ、失敗・15秒以内に完了確認できない場合を表示。設定を閉じると更新用リロードのイベントを解除し、その後の編集中に遅れたイベントで再読み込みしません。
- Netlifyのルート文書 `/` とManifestにもno-cacheを設定。既存のsw.js/index.html再検証設定を維持しました。
- SWのDBアクセス・削除処理は追加していません。既存のビルドハッシュによるキャッシュ更新、確認後の適用、オフライン起動を維持します。新しい版の取得には通信が必要です。

iPhoneではSafariでURLを直接開き、共有 → ホーム画面に追加 → 追加。表示される場合は「Webアプリとして開く」をオンにします。最初にオンラインで設定のオフライン準備完了を確認してください。ホーム画面からのアプリ表示はOSのPWA機能によるもので、通常のSafariタブのアドレスバーをアプリ側が消す仕組みではありません。

## 測定

同じクラウドChromiumで7回計測した中央値（UTF-16長、カウント関数単独）：

| 本文長 | 修正前の詳細カウント | 修正後 |
| ------ | -------------------- | ------ |
| 10,000 | 4.5ms                | 3.0ms  |
| 50,000 | 13.4ms               | 11.6ms |

通常表示では詳細カウント自体を行わず、改行を除いた文字数のみ計算します。上記は実機FPSやキー入力から描画までの時間ではなく、60fpsを保証しません。

大量の絵文字を含む長文の最初のテストでは、Playwrightの一括fillに時間がかかり30秒制限に達しました。アプリなしの標準textareaでも同じ入力命令が約19.6秒かかることを確認。一方、同じ3,000行をアプリへクリップボードから実際に貼り付けてカウントを表示するまで約0.36秒でした。テストを実際の貼り付け操作へ変更し、内容・詳細カウント・Undo・自動保存・再読み込みを確認しています。入力が遅いことを単にタイムアウト延長で隠す対応はしていません。
