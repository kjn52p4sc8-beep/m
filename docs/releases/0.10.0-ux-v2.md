## 操作・画面の改善

- メモの＋は即座に新規編集、ToDoの＋は入力欄へ移動。位置・丸型デザインは維持しています。
- 検索アイコンは、メモではメモ検索、ToDoではToDo専用検索。スクロール位置と検索状態は画面ごとに保持します。
- ごみ箱は「選択 → 対象をチェック → 復元/完全削除」。選択中は＋を隠し、0件時は一括操作を無効化します。表示は50件ずつ、全選択は未表示の対象も含みます。
- フォルダは行を長押し→上下移動→指を離すと保存。長押し成立前の縦移動は通常スクロールです。編集・削除ボタンはドラッグ対象外です。Space/上下キー/Enter、Escapeによる操作も可能です。
- 編集画面は通常、補助設定を閉じて本文を表示。「挿入・設定」から選んだ設定欄を開き、再選択・「本文へ戻る」ができます。録音・画像保存中に補助欄を閉じて処理を破棄しないよう制御しています。
- 390×844pxのChromiumでは、本文入力欄の高さ606px、下部ツール96px、ページ横幅390pxを実測しました（セーフエリア追加なしの条件）。本文とツールは重なりません。これはiPhone実機での表示寸法を保証する値ではありません。

## 安定性・原因と対策

- 既存ToDoがメモ一覧に混在：保存データには分類がある一方、一覧が全件を使用していました。表示・検索の入力データを既存分類で絞り込みました。
- 日本語変換への配慮が不足：変換中も通常の文字色重ね描画・500ms自動保存が動く構成でした。compositionイベントでネイティブ描画へ切り替え、DB書き込みを確定まで待ち、確定文字列に色を再適用します。1回の変換を1回のUndoにまとめます。実機での重複表示が再現確認済みという意味ではありません。
- 補助UIで本文が狭い：常時表示の補助見出しと本文高さの上限を整理。表示領域に応じて本文を広げ、固定ツール内のパレットが画面外へずれない配置にしました。
- 複数削除の不整合：選択IDを検証し、本文・添付・通知等を同じトランザクションで処理。途中失敗・対象がごみ箱から移動した場合は部分削除しません。
- 並び替えの競合：保存時に同じカテゴリーの現存フォルダID一式を検証。作成・削除で内容が変わった場合は保存を拒否し、確認・再試行を促します。
- 二重作成・中断：フォルダ作成とごみ箱一括処理に即時ロック。ドラッグのタイマー・イベント・アニメーションフレームを終了/非表示/アンマウント時に解除します。

- ToDo追加直後の再読み込み：IndexedDBの非同期保存が完了する前に終了すると項目が残らないケースを本番PWAテストで再現。送信操作時にlocalStorageへ一時記録し、起動時に復旧します。保存済み・編集済み・ごみ箱内の同じIDは重複追加しません。一時保存の失敗は入力欄を残して表示します。
