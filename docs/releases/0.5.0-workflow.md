# My Memo 0.5.0 作業報告

最終確認日：2026年10月30日（日本時間）。既存React / TypeScript / Vite / Tailwind CSS / Dexieアプリを拡張。実行時の依存追加なし。

## 実装済み

- ホーム・検索・フォルダのメモ一覧で左スワイプ／「…」から削除。無題も対応。縦方向のスクロールと区別し、スワイプ直後の誤クリックを抑止。確認後ごみ箱に移動、12秒間の取り消し、設定から復元。画像・録音・色・分類など元のデータを保持。完全削除はごみ箱から確認後のみ。自動削除なし。
- 既存チェックリストを継続利用。ホームからToDo追加、一覧から直接入力、任意の期限・通知日時・内容の編集、完了／未完了、期限順表示、完了項目の折りたたみ。専用の「やること」メモをカテゴリーごとに再利用。
- 通知は期限当日・前日・指定日時。ユーザーが設定するときだけ許可を要求。アプリ表示中に確認し、次回起動時は期限超過を表示。同じ項目・時刻の重複通知をDBで抑止。期限変更・完了・削除・通知オフを反映。非表示へ切り替わった確認処理を中断しても通知済み記録を消費しない。
- 「種類 → URL・テキストを保存」で貼り付け、任意タイトルとメモを保存。HTTPS/HTTPのみリンク化し、認証情報入りURLを拒否。YouTube等のサービス名を表示。動画・投稿・サムネイルの取得なし。
- 編集画面から共有内容を確認・変更し、端末共有メニュー／コピー。共有非対応・権限拒否時は手動コピー案内。画像・音声・表・旅行・貸し借りの記録は自動送信しない。
- 通常メモは＋の1タップ、ToDoはホームの1タップで入力画面、検索は従来どおり1タップ。44pxタップ領域、下部の余白、キーボード時の作成バー非表示、320px編集ツールバーのはみ出しを修正。

## 対応できない条件と外部サービス

**アプリを閉じている間の通知配信は未実装。** この構成はブラウザ内保存のみで、配信サーバー・Push購読・スケジューラーがない。iOS/iPadOSのWeb Pushは16.4以降、HTTPS・ホーム画面に追加したPWA・ユーザー許可が必要。今のアプリは表示中の通知と次回起動時のお知らせを提供する。

バックグラウンド配信には、通知予定を保存するサーバー、期限変更／削除と連動する配信ジョブ、Push購読管理、サーバーだけで保持するVAPID秘密鍵が必要。共有端末の通知内容や購読解除・期限切れ処理も設計する。外部へ送る情報と利用料金を説明し同意後に導入する。この更新では外部契約・課金・サーバーへのメモ送信は行っていない。将来費用は事業者・契約プラン・配信量次第で、現時点の金額は未確認。

**iPhoneで他アプリの共有先にMy Memoを直接表示する機能は未実装。** Safari/iOSはWeb Share Target非対応のため、貼り付け保存を提供。My Memoから外へ送るWeb Share APIは別機能。ネイティブの共有拡張には将来Capacitor等とiOSアプリ側の実装が必要。

確認根拠：MDN Browser Compat Data 8.1.7（2026-10-29取得、[抜粋](0.5.0-browser-compat.json)）。[Web Share Target](https://developer.mozilla.org/docs/Web/Progressive_web_apps/Manifest/Reference/share_target)、[Service Worker通知](https://developer.mozilla.org/docs/Web/API/ServiceWorkerRegistration/showNotification)、[WebKit Web Push仕様](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)。この環境ではWebKit記事への直接アクセスは403、互換データをnpm配布物から確認した。
