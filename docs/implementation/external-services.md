- Supabase公式料金：https://supabase.com/pricing — プラン、認証利用者数、DB／添付保存量、転送量、Realtime利用量を確認。
- Netlify公式料金：https://www.netlify.com/pricing/ — 現在の契約と、関数実行・帯域・ビルド／デプロイの枠を確認。

- OpenAI API料金：https://openai.com/api/pricing/ — 要約等の入出力トークン、文字起こしの音声量に応じた従量料金。

## 実装する順序

1. ステージング用プロジェクト・公開URL・プロバイダーと費用上限を確定。
2. サーバー側の認証と行単位アクセス制御を実装・否定ケースをテスト。
3. 個人メモだけの同期と明示的なローカル移行を検証。
4. オフライン編集・競合・添付転送の再試行を検証。
5. 招待・グループ・役割・編集履歴・共有解除。
6. 同意画面と料金表示を含む任意のAI処理。

## サーバー側で必須の保護

- メモの所有者と共有先を分離。初期値は非公開。旅行・貸し借りも通常は非公開。
- メンバーのviewer/editor/admin権限をDBポリシーとサーバーの両方で検証。UIを隠すだけで済ませない。
- グループIDやメモIDを書き換えた他人のアクセス、削除後のアクセス、権限昇格、添付のURLアクセスを拒否するテスト。
- 招待は十分な乱数・有効期限・ハッシュ保存・使用回数制限・失効処理を備える。QRには同じ招待URLだけを格納し、情報や秘密鍵を埋め込まない。
- メモにrevisionを持ち、更新は比較してから保存。競合時は両版を保持して選択・統合できるようにし、後勝ち上書きで消さない。リアルタイム配信だけでは競合は解決しない。
- ログインユーザーごとのローカル領域とアップロード待ちキューを分離。ログアウトで既存ローカルメモを削除しない。別アカウントへ勝手にアップロードしない。
- UUIDを保った冪等な移行（owner + local IDの一意制約）、件数とチェックサムの照合、移行前JSON、失敗時の再試行。移行成功前のローカル削除は禁止。
- 貸し借りは本人が選択した情報だけを共有。個人メモ全体を自動公開しない。
- AI送信はメモ／音声の対象を明示して同意を取得。履歴・課金上限・取消可能な提案を設け、キーは関数の環境変数に保存。
