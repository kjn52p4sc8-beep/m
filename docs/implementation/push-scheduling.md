# バックグラウンド通知の対応範囲と導入設計

2026-11-03 / My Memo 0.9.0

## この版で動く範囲

IndexedDB v11の`schedules`に設定・次回日時・一時停止中の残り時間・通知済み日時を保存します。タイマーは絶対日時から残り時間を計算し、画面上の1秒ごとの更新回数には依存しません。繰り返しは作成時のIANAタイムゾーン・曜日・時間帯で次回を計算します。メモ・ToDoへの紐付け、完了・削除時の停止も同じDBトランザクションで処理します。

通知予定の確認はアプリが表示されているときだけです。編集画面とアプリの主要ダイアログでは待機します。アプリを閉じている間や画面ロック中には通知しません。再開時、各設定につき過ぎた予定を1回表示し、繰り返しは次の未来の予定へ進めます。複数タブではDBの排他的トランザクションで先に取得したタブだけが表示します。通知済みを先に記録するため、記録直後にOSが終了した場合は表示を保証できません。

端末通知を許可した環境では、アプリ内のお知らせと併せて、稼働中のService Workerの`showNotification`を使用します。対応するデスクトップ環境ではNotification APIへフォールバックします。クリックは対象メモを開きます。別メモを編集中なら、編集を閉じるまで待ってから開き、未保存内容を破棄しません。

## iPhoneの条件

- 端末通知はiOS/iPadOS 16.4以降のホーム画面追加版、HTTPS、ユーザー操作による通知許可が前提です。Safariの通常タブ・アプリ内ブラウザでは条件を満たさない場合があります。
- 許可要求は保存・開始ボタン操作時だけ行い、拒否や非対応理由を画面に表示します。通知のオンはアプリ内のお知らせを含む設定です。Push配信がオンになったという表示はしません。
- Service Workerは常時動くプロセスではありません。ページ内タイマーやService Workerだけでは、終了後の指定時刻配信を保証できません。
- この版はPush購読の作成やPush配信を行いません。実際のiPhoneでの共有シート、端末通知、画面ロック、OSの省電力動作は未検証です。

仕様参照： [WebKit: Web Push for Web Apps on iOS and iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)、[MDN: Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[MDN: Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)。実装環境では配布元・一部外部サイトへの通信が403となるため、最新の端末条件を実機でも確認してください。

## 閉じていても届く構成（未実装）

1. 認証と利用者ごとのアクセス制御を持つAPI・DBを用意する。既存のローカルデータはそのまま保持し、利用者が明示した通知だけをアップロードする。
2. ユーザー操作でPushManagerの可否を確認し、許可後にPush購読を取得する。購読URL・暗号鍵はアクセス制御されたサーバーに保存し、ログへ出さない。VAPID秘密鍵はサーバー環境変数だけに置く。
3. サーバー側スケジューラーがUTCの`nextAt`を処理し、IANAタイムゾーンで次回を計算する。スケジュールID・版・予定日時による一意制約と送信キューを使い、再試行の重複を抑制する。
4. 変更・完了・削除で版を更新し、未送信の旧ジョブを無効化する。配信直前にも有効状態を確認する。既に端末へ配信された通知を必ず回収することは保証しない。
5. Service Workerにpush受信処理を追加する。内容は必要最小限とし、ロック画面にメモ本文・相手名・金額を出す設定は初期状態で無効にする。クリック後もアクセス権限を再確認する。
6. オフライン操作を再接続時に同期する。サーバーへ未送信・取消未反映の状態を表示する。ログアウト時には購読とサーバー予定の扱いを確認し、端末メモを削除しない。
7. アプリ終了・画面ロック・省電力・圏外・複数端末・許可撤回・夏時間・購読失効を実機テストする。Web Pushでも配送遅延・失敗があり、秒単位の厳密な時計アラームは保証しない。

Netlifyの静的公開だけでは予定DBや継続的な配信基盤はありません。導入時に認証・DB・サーバー定期実行・Push送信のサービスとプランを選定します。必要な設定はプロジェクトID、許可ドメイン、認証プロバイダー、DBポリシー、VAPID鍵、定期実行頻度です。料金はサービス・契約プラン・配信数で変わるため、この段階では未確定です。サービス選定時に最新料金とデータの送信先を提示してから導入します。この版に追加サービス利用料はありません（既存ホスティング等の費用は別）。
